# 通用 OCR 验证记录

## 实现

新增 `generic` 档案，使用 RapidOCR + ONNX Runtime，不依赖固定显示屏模板。

处理流程：

1. 抽样帧检测屏幕文字和主读数区域；
2. 自动尝试 0°、90°、180°、270°；
3. 识别数字并过滤日期、时间、菜单、百分比和最大值；
4. 用天平标准砝码判断主读数和 `g/mg`；
5. 固定 ROI 后只执行文字识别，避免每帧重复完整检测；
6. 按稳定时间聚合九次称量。

未知天平编号会自动回退到 `generic`。F001/F002/F003 仍优先使用专用档案，
F004/F005 当前使用通用档案；
当专用档案少于九次时，也会尝试通用档案。

## 图形屏截图验证

以下结果使用交付锁定的 RapidOCR `1.2.3` 复测。`1.4.4` 仍可从 PyPI 安装，但它声明
仅支持 Python `<3.13`，不能在本次 Python 3.13 部署环境中解析；切到 `1.2.3` 后识别值
保持正确，但置信度低于旧版本记录，交付时仍应以人工复核结果为准。

| 样本 | RapidOCR 1.2.3 结果 | 置信度 |
| --- | --- | --- |
| Sartorius 图形屏 | 49.99994 g | 78.3% |
| Sartorius 图形屏（带“原图下载失败”遮罩） | 49.99988 g | 76.5% |
| Mettler 图形屏（侧转拍摄） | 20.00025 g | 90.0% |

三张图形屏均正确提取主读数并排除菜单、日期和遮罩文字。

RapidOCR 1.2.3 在检测模式与纯文字识别模式下返回的字段位置不同，代码已兼容
“框、文字、置信度”和“文字、置信度”两种结构，并增加 3 项结构回归测试。

当前素材库没有一条“普通图形屏设备连续完成九次称量”的完整视频，因此本记录只能
证明截图识别和算法单元行为，不能宣称通用 OCR 已完成九次称量的整片验收。新增设备
交付前仍应补拍一条同类完整视频。

## 七段数码管验证

对现有 F001、F002、F003 七段码视频使用 `generic` 整片识别，均未得到九次称量。
这类显示屏继续使用专用模板，精度和速度更高：

- `f001` / `f001_mg`
- `f002a` / `f002b` / `f002c`
- `f003`

## 结论

通用 OCR 已可用于普通图形屏、触摸屏和新品牌数字文字界面。七段数码管不是通用
文字 OCR 的强项，不能删除现有专用档案；最终方案采用“专用模板优先、通用 OCR 兜底”
的混合架构。
