# 天平校验系统人工核验清单

> 用途：验收、试运行和正式使用前逐项确认。
> 说明：系统自动识别不能替代操作人员对现场设备、人员身份和过程信息的确认。

## 一、每次校验必须人工确认

- [ ] 当前登录账号与实际操作人员一致。
- [ ] 人员卡由实际检验人员持有，卡号清晰可见，并与视频识别结果一致。
- [ ] 新入职、换卡或停用人员已由管理员在“人员与权限”中同步变更。
- [ ] 旧卡已回收，解绑或替换后的旧二维码不再使用。
- [ ] 视频中的人员卡、天平编号与实际设备和本次校验任务一致。
- [ ] 上传时选择的天平与实际拍摄天平一致。
- [ ] 上传时填写的实际拍摄开始时间正确。
- [ ] 视频没有遮挡显示屏、严重抖动、失焦或关键片段丢失。
- [ ] 已确认天平清洁状态。
- [ ] 已确认水平调节状态。
- [ ] 已确认内部校正结果；设备不适用时选择 `NA`。
- [ ] 九次称量已逐行核对：
  - [ ] 标称砝码值正确。
  - [ ] 左、右量程归属正确。
  - [ ] 显示数值与视频一致。
  - [ ] `g` / `mg` 单位正确。
  - [ ] 换算后的克值正确。
  - [ ] 测量时间与实际视频时间一致。
  - [ ] 每次限度与合格/超差结论正确。
- [ ] 识别置信度低或异常帧较多时，已重点查看原始视频。
- [ ] 自动识别结果有不一致时，已人工修正；不得只修改结论而不核对原始示值。
- [ ] 整机外部校正结论与九次明细一致。
- [ ] 备注中已说明异常、重拍、人工修正或其他需要复核的情况。
- [ ] 手工补录记录填写了真实、明确的原因。
- [ ] 检验人员姓名、提交时间正确，记录可以提交复核。

## 二、人员身份核验

- [ ] 匹配测试：使用本人账号上传包含本人卡号的视频，页面显示“人员卡核验通过”。
- [ ] 不匹配测试：使用另一账号上传同一人员卡视频，识别应为 `FAILED`，且不生成校验记录。
- [ ] 缺卡测试：上传没有人员卡的视频，可以生成草稿，但页面和备注均出现“人工核验身份”提示。
- [ ] 已确认业务是否要求“缺卡禁止提交”。当前系统只警告，不强制阻断。
- [ ] 人员卡在真实光照、角度、距离下可被识别；合成二维码测试不能替代此检查。
- [ ] 视频内存在多张卡或卡号冲突时，已人工确认实际应由哪名人员完成校验。

## 三、移动端与局域网

- [ ] 手机与电脑连接同一局域网。
- [ ] 电脑工作台显示的二维码地址使用正确网卡 IP。
- [ ] 手机扫描二维码后能打开 `/mobile` 页面。
- [ ] 手机登录账号与实际检验人员一致。
- [ ] 手机可选择已有视频或调用相机拍摄。
- [ ] 手机上传过程中显示进度，暂停或失败时有明确提示。
- [ ] 手机上传完成后，电脑端出现相同视频和记录。
- [ ] 手机可以关闭页面，电脑端异步识别仍继续。
- [ ] 识别完成后，电脑端可以看到九次称量和人员身份提示。
- [ ] Windows 防火墙已允许实际使用的前端与后端端口。
- [ ] 如果电脑有多个网卡、VPN 或 Wi-Fi，已通过 `APP_PUBLIC_URL` 固定正确地址。
- [ ] 使用真实手机完成一次完整上传；移动浏览器视口测试不能替代实体手机验收。

## 四、识别质量和异常处理

- [ ] 当前设备显示档案选择正确：`f001`、`f001_mg`、`f002a`、`f002b`、`f002c` 或 `f003`。
- [ ] 显示区域未发生变化；更换机位后已重新标定。
- [ ] 自动识别为 `PASS`，且九次示值均能在视频中找到对应稳定片段。
- [ ] 自动识别为 `FAIL` 时，已确认是真实超差，而不是识别失败。
- [ ] 置信度低于 55% 时已进行人工重点复核。
- [ ] 异常帧超过总帧数 80% 时已检查视频质量。
- [ ] 末位跳动、去皮段和过渡段没有被误当成有效称量。
- [ ] 同一称量的重复稳定段没有造成九次称量重复或缺失。
- [ ] 新增天平已提供足够标定截图，并完成新模板和新档案验证。
- [ ] 新增档案至少完成一组合格样机视频和一组故障/低质量视频测试。

## 五、复核与记录归档

- [ ] 复核人员确认检验人员身份、人员卡核验状态和视频来源。
- [ ] 复核人员逐项查看九次测量明细、限度和偏差曲线。
- [ ] 低置信度、缺卡、人工修正内容均有复核意见。
- [ ] 退回时已填写明确原因，检验人员可以据此修改。
- [ ] 复核通过后记录锁定，不能再修改。
- [ ] 错误通过或不应继续使用的正式记录已由管理员填写作废原因，而不是直接物理删除。
- [ ] 作废后九次明细、作废人、作废时间和审计日志仍然保留。
- [ ] 作废记录不能继续编辑、提交、复核或解锁。
- [ ] 记录表 PDF 为 A4 单页或正确分页，无文字截断、重叠或乱码。
- [ ] PDF 中记录编号、天平、唯一号、人员、九次数据、结论、备注和签名栏完整。
- [ ] 已作废记录的 PDF 明确显示“已作废”、作废人、作废时间和原因。
- [ ] PDF 下载权限只开放给复核确认人员和管理员。
- [ ] 已确认 PDF 当前为光栅页面，不能全文检索。

## 六、交付与运行安全

- [ ] 正式数据库已执行最新迁移脚本。
- [ ] 测试数据库、测试视频、测试记录和调试进程已清理。
- [ ] 正式上传目录位于非系统盘，容量和权限满足要求。
- [ ] 正式环境已设置正确的数据库口令、上传目录和手机入口 URL。
- [ ] 检验人员只能查看自己的视频和记录。
- [ ] 复核人员不能创建校验记录。
- [ ] 非管理员不能访问用户列表、操作日志和模板维护。
- [ ] 并发提交、复核和识别测试结果符合预期。
- [ ] 后端重启后，已检查是否存在长期停留在 `ANALYZING` 的任务。
- [ ] 数据库与上传目录的备份、恢复流程已经实际演练。
- [ ] 已明确系统是否需要多实例部署；如需要，必须先实现共享 Session 和持久化任务队列。

## 七、必须由业务方决定的规则

- [ ] 未检测到人员卡时，是“允许提交并人工核验”，还是“禁止提交”。
- [ ] 识别置信度低于多少时必须强制人工修正。
- [ ] 异常帧比例超过多少时必须拒绝自动建单。
- [ ] 人员卡不匹配时是否允许重新选择正确视频，还是必须重新拍摄。
- [ ] 自动识别结果允许人工修改哪些字段。
- [ ] 视频、PDF 和审计日志的保存年限与归档责任。
