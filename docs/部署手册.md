# 天平校验视频分析系统 部署手册

> 适用版本：0.1.0-SNAPSHOT（批次 3 至 8）
> 部署形态：单机内网离线部署，数据库、后端、前端与识别服务同一台工作站

## 一、交付物

```text
balance-check-<版本>/
├─ VERSION.txt            版本、构建时间、Git 提交
├─ README.md              项目说明与开发指引
├─ backend/
│  └─ balance-check.jar   可执行后端（内嵌 Tomcat，端口 8081）
├─ frontend/              前端静态文件（index.html、assets/）
├─ analysis/              视频识别脚本、依赖清单与标定模板
├─ database/
│  ├─ schema.sql          建表脚本（11 张表）
│  └─ seed.sql            演示账号与五台天平
├─ docs/                  设计说明书、部署手册、测试报告、交付清单
└─ scripts/               环境检查、建库、启停、测试与打包脚本
```

交付包由 `scripts/package-release.ps1` 生成，`scripts/verify-release.ps1` 校验；构建产物在 `dist/` 下，不纳入版本库。

## 二、环境要求

| 组件 | 版本 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| 操作系统 | Windows 10/11 或 Windows Server | PDF 导出使用系统中文字体；Linux 需自行安装 Noto/文泉驿中文字体 | 必需（PDF 导出） |
| JDK | 17 及以上（验证 23、25） | 运行后端 | 必需 |
| MySQL | 8.0 及以上（验证 9.4） | 业务数据 | 必需 |
| PowerShell | 7（接口测试）；5.1 可运行部署脚本 | 运维与测试 | 必需 |
| Node.js | 20 及以上（验证 24） | 前端开发与构建 | 仅构建前端 |
| Python | 3.11-3.12（推荐并验证 3.12） | 运行视频识别脚本；RapidOCR 1.4.x 不支持 Python 3.13 | 必需 |
| OpenCV / NumPy | 见 analysis/requirements.txt | 七段码与字符识别 | 必需 |
| RapidOCR / ONNX Runtime | 见 analysis/requirements.txt | 通用图形屏文字识别 | 必需 |
| ffmpeg | 任意较新版本 | 视频抽帧（优先） | 必需 |
| ffprobe | 与 ffmpeg 同版本 | 上传时校验真实视频流 | 必需 |

部署前先执行环境检查，脚本会检查 JDK、Node、MySQL 客户端、ffmpeg、端口与存储盘：

```powershell
pwsh -File scripts\check-environment.ps1 -UploadDir D:\develop\balance-check-data\uploads
```

安装识别依赖：

```powershell
python -m venv analysis\.venv
analysis\.venv\Scripts\python.exe -m pip install -r analysis\requirements.txt
```

RapidOCR 模型随 Python 包本地加载，不需要联网 OCR 服务。已知七段数码管天平仍优先
使用专用模板；未知普通图形屏天平使用 `generic` 档案和数据库中的标准砝码自动校验主读数。
当前锁定 `rapidocr_onnxruntime==1.2.3`，并在 Python 3.12.14 完整验证；不要在交付环境
临时升级依赖版本。

Windows 安装 ffmpeg（下载后校验官方 SHA-256）：

```powershell
pwsh -File scripts\install-ffmpeg.ps1
```

默认安装到 `D:\develop\ffmpeg\bin\ffmpeg.exe`，启动脚本会自动识别；也可通过
`APP_RECOGNITION_FFMPEG` 指向已有文件。若 ffmpeg 不可用，识别脚本会使用
OpenCV 解码兜底，但正式部署仍应安装 ffmpeg。

## 三、数据库初始化

方式一（推荐，脚本会提示输入 root 口令并创建应用专用数据库账号）：

```powershell
pwsh -File scripts\init-database.ps1 `
  -Server localhost -Port 3306 -User root `
  -AppUser balance_app -AppPassword '<应用数据库强口令>'
```

方式二（手工执行，注意使用 utf8mb4，避免中文乱码）：

```powershell
cmd /c "mysql -uroot -p --default-character-set=utf8mb4 < database\schema.sql"
cmd /c "mysql -uroot -p --default-character-set=utf8mb4 < database\seed.sql"
```

导入后确认：

```sql
SELECT COUNT(*) FROM balance_check.sys_user;   -- 4 个演示账号
SELECT COUNT(*) FROM balance_check.balance;    -- 5 台天平
```

已有数据库升级时，`scripts\init-database.ps1` 会在 schema/seed 后按文件名执行
`database/migrations/*.sql`，为 `video` 表补充人员卡、身份核验、识别档案、
置信度、异常帧与拍摄时间字段，并为 `sys_user` 增加会话版本号。迁移脚本可重复执行。

演示账号：admin（管理员）、liyi / lier（检验人员）、qiyi（复核确认人员）。
初始口令由本地 `.local/runtime.env.ps1` 中的 `BALANCE_DEMO_PASSWORD` 提供，
不得写回仓库或前端代码。

## 四、后端配置

`backend/src/main/resources/application.yml` 中所有部署相关项都写成 `${环境变量:默认值}`，交付到新机器时无需改文件：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| SERVER_PORT | 8081 | 后端端口 |
| DB_URL | jdbc:mysql://localhost:3306/balance_check?... | 数据库连接串 |
| DB_USERNAME | balance_app | 应用专用数据库账号，仅授予业务表增删改查权限 |
| DB_PASSWORD | 无默认值 | 必须由环境变量或 `.local/runtime.env.ps1` 提供 |
| APP_ALLOWED_ORIGIN_PATTERNS | 前端 5173 的同机与局域网来源 | CORS 白名单 |
| SESSION_COOKIE_SECURE | false | HTTPS 正式部署必须设为 true |
| APP_UPLOAD_DIR | D:/develop/balance-check-data/uploads | 视频存储目录 |
| UPLOAD_MAX_FILE | 1GB | 单文件上限 |
| UPLOAD_MAX_REQUEST | 1100MB | 单请求上限 |
| SESSION_TIMEOUT | 8h | 会话有效期 |
| APP_RECOGNITION_PYTHON | python | 识别使用的 Python 解释器 |
| APP_RECOGNITION_SCRIPT | ../analysis/analyze_video.py | 识别入口脚本，后端会自动查找项目内 analysis 目录 |
| APP_RECOGNITION_FFMPEG | 自动查找 `D:\develop\ffmpeg\bin\ffmpeg.exe`，否则 `ffmpeg` | ffmpeg 可执行文件 |
| APP_RECOGNITION_FFPROBE | 自动查找 ffmpeg 同目录的 `ffprobe.exe` | 上传视频内容校验 |
| APP_RECOGNITION_TIMEOUT | 600 | 单段视频识别超时秒数 |
| `app.recognition.device-profiles`（YAML） | F001/F002 | 天平编号到候选显示档案的映射；新增设备时直接编辑该项 |
| APP_PUBLIC_URL | 自动探测局域网 IP | 手机入口外部 URL，不包含 `/mobile` |
| APP_MOBILE_PORT | 5173 | 未配置 APP_PUBLIC_URL 时二维码使用的手机页端口 |
| APP_VIDEO_DELETE_SOURCE | true | 识别成功后是否删除源视频；false 表示保留原始视频作为证据 |

设置示例（当前 PowerShell 会话生效）：

```powershell
$env:DB_PASSWORD = 'your-password'
$env:DB_USERNAME = 'balance_app'
$env:APP_UPLOAD_DIR = 'D:\balance-check-data\uploads'
$env:APP_RECOGNITION_PYTHON = 'D:\balance-check\analysis\.venv\Scripts\python.exe'
$env:APP_RECOGNITION_FFMPEG = 'D:\tools\ffmpeg.exe'
$env:APP_PUBLIC_URL = 'http://192.168.1.100'
$env:SESSION_COOKIE_SECURE = 'true'
```

视频不要放在 C 盘或 OneDrive 同步目录。默认策略是**识别成功后删除源视频**并把
`video.relative_path` 置空：释放磁盘，换机器演示也不再依赖旧文件；识别失败会保留文件以便重试。
若甲方要求留存原始视频作为证据，设置 `APP_VIDEO_DELETE_SOURCE=false`，并按每天 20 台、
单条 30MB 估算约 600MB/天规划磁盘，建议每季度归档一次。源视频清理后，工作台不再显示
“重新识别”，记录详情与 PDF 导出不受影响。

PDF 记录表由 Java2D 渲染，按 Microsoft YaHei → SimSun → Noto Sans CJK SC →
WenQuanYi Micro Hei 的顺序选择系统字体；精简版 Windows Server 若缺少中文字体，
PDF 会显示方框，需要先安装中文字体。

手机与电脑连接同一局域网后，在检验工作台扫描“手机上传入口”二维码，或访问
`http://<电脑局域网IP>:5173/mobile`。开发模式 Vite 已监听 `0.0.0.0`；如手机
无法访问，请检查 Windows 防火墙是否允许前端端口和 8081 后端端口。

## 五、启动与停止

交付包内直接启动（自动等待健康检查）：

```powershell
pwsh -File scripts\start-backend.ps1 -Port 8081
```

脚本会用后台进程运行 `java -jar backend\balance-check.jar`，把日志写到 `logs/`，并把进程号写入 `logs\backend.pid`。停止：

```powershell
pwsh -File scripts\stop-backend.ps1
```

也可以手工启动：

```powershell
java -jar backend\balance-check.jar
```

健康检查：`GET /api/system/health` 返回服务状态、磁盘容量与可写状态，不暴露服务器绝对路径。浏览器打开 <http://localhost:8081>。

## 六、前端部署

开发模式（5173 端口，Vite 已把 /api 代理到 8081）：

```powershell
cd frontend
npm install
npm run dev
```

生产模式二选一：

1. 由后端托管：把 `frontend/dist` 的内容复制到后端静态资源目录（或作为独立静态目录由运维配置），访问 8081。
2. 由 Nginx 托管，后端只提供 /api：

```nginx
server {
    listen 80;
    server_name balance.local;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name balance.local;
    client_max_body_size 1100m;

    ssl_certificate     D:/balance-check/certs/balance.local.crt;
    ssl_certificate_key D:/balance-check/certs/balance.local.key;

    root   D:/balance-check/frontend;
    index  index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;   # history 路由回退
    }
}
```

## 七、构建与校验交付包

```powershell
pwsh -File scripts\package-release.ps1                # 构建并打包，输出 dist/balance-check-<版本> 与同名 zip
pwsh -File scripts\package-release.ps1 -SkipFrontend   # 只打包后端（前端依赖未安装时）
pwsh -File scripts\verify-release.ps1 -Path dist\balance-check-0.1.0-SNAPSHOT   # 校验交付包完整性
```

打包脚本按顺序执行：`mvnw -DskipTests package` → `npm run build` → 复制 jar、前端静态文件、数据库脚本、识别脚本与模板、文档与脚本 → 生成 VERSION.txt → 压缩 zip。`.venv` 不进入交付包，部署机需按本手册安装 Python 依赖。已有 Maven 缓存可直接复用；新机器首次构建允许联网补齐缺失依赖。

## 八、日常运维

- 健康检查：定时请求 `/api/system/health`，关注 `storage.freeGb` 与 `storage.writable`。
- 备份：执行 `pwsh -File scripts\backup.ps1 -Password <口令> -IncludeUploads`，生成数据库 SQL、上传文件、SHA-256 清单和 ZIP。
- 归档：已复核记录的视频可每季度移到离线介质，数据库保留元数据即可追溯。
- 日志：后端日志在 `logs/`（start-backend.ps1 启动时），按需清理；审计日志在数据库 `audit_log` 表，管理员可在"操作日志"页查询。

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动即退出，日志提示连接失败 | 数据库未启动、口令不对或库不存在 | 先执行 init-database.ps1；核对 DB_URL / DB_PASSWORD |
| `Public Key Retrieval is not allowed` | MySQL 8 使用 caching_sha2_password | 连接串已默认 `allowPublicKeyRetrieval=true`，如自建连接串需保留 |
| 中文显示为问号 | 客户端字符集不是 utf8mb4 | 导入时加 `--default-character-set=utf8mb4` |
| 端口 8081 被占用 | 上一次后端未退出 | `scripts\stop-backend.ps1`，或换 `-Port` |
| 刷新页面 404 | 前端 history 路由未回退 | Nginx 加 `try_files $uri $uri/ /index.html` |
| 上传大文件失败 | 超过 1GB 限制 | 调整 UPLOAD_MAX_FILE、UPLOAD_MAX_REQUEST 与反向代理 client_max_body_size |
| 识别失败并提示缺少 cv2/numpy | Python 环境未安装识别依赖 | 在 analysis 目录安装 requirements.txt，并设置 APP_RECOGNITION_PYTHON |
| 识别失败并提示找不到 ffmpeg | ffmpeg 不在 PATH | 设置 APP_RECOGNITION_FFMPEG 为 ffmpeg.exe 绝对路径 |
| 人员卡号不一致 | 视频 QR 卡号与登录账号 `card_no` 不同 | 使用本人账号上传，或由授权人员核对人员卡 |
| 页面提示需重点复核 | 置信度低于 55 或异常帧超过 80% | 检查画面稳定性、显示区域与标定档案 |
| 手机扫描二维码后无法打开 | 电脑 IP 变化、手机不在同一局域网或防火墙拦截 | 重新打开工作台刷新二维码，并检查局域网与防火墙 |
| 脚本无法执行 | 执行策略 | `powershell -ExecutionPolicy Bypass -File <脚本>` |
| 离线安装前端依赖失败 | 无外网 | 在可联网机器 `npm install` 后整体拷贝 node_modules，或用内网镜像 |

## 十、卸载与回滚

1. `scripts\stop-backend.ps1` 停止后端；
2. 备份数据库与 `APP_UPLOAD_DIR`；
3. 回滚时用上一版本交付包替换，数据库结构在批次 3 之后未变更，可直接复用；
4. 确认不再需要后再删除旧目录与数据库。

数据库恢复：

```powershell
cmd /c "mysql -uroot -p balance_check < D:\backups\balance_check\database.sql"
```

恢复前应先停止后端。视频文件从备份的 `uploads` 目录复制回 `APP_UPLOAD_DIR`。恢复后检查
`/api/system/health`、人员卡号、天平清单和记录数量。
