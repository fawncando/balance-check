# 天平校验视频分析系统 部署手册

> 适用版本：0.1.0-SNAPSHOT（批次 3 至 8）
> 部署形态：单机内网离线部署，数据库、后端、前端与识别服务同一台工作站

## 一、交付物

```text
balance-check-<版本>/
├─ VERSION.txt            版本、构建时间、Git 提交
├─ README.md              项目说明与开发指引
├─ backend/
│  └─ balance-check.jar   可执行后端（内嵌 Tomcat，端口 8081）
├─ frontend/              前端静态文件（index.html、assets/）
├─ database/
│  ├─ schema.sql          建表脚本（11 张表）
│  └─ seed.sql            演示账号与两台天平
├─ docs/                  设计说明书、部署手册、测试报告、交付清单
└─ scripts/               环境检查、建库、启停、测试与打包脚本
```

交付包由 `scripts/package-release.ps1` 生成，`scripts/verify-release.ps1` 校验；构建产物在 `dist/` 下，不纳入版本库。

## 二、环境要求

| 组件 | 版本 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| JDK | 17 及以上（验证 23、25） | 运行后端 | 必需 |
| MySQL | 8.0 及以上（验证 9.4） | 业务数据 | 必需 |
| PowerShell | 7（接口测试）；5.1 可运行部署脚本 | 运维与测试 | 必需 |
| Node.js | 20 及以上（验证 24） | 前端开发与构建 | 仅构建前端 |
| ffmpeg | 任意较新版本 | 批次 4 识别抽帧 | 识别功能需要 |

部署前先执行环境检查，脚本会检查 JDK、Node、MySQL 客户端、ffmpeg、端口与存储盘：

```powershell
pwsh -File scripts\check-environment.ps1 -UploadDir D:\develop\balance-check-data\uploads
```

## 三、数据库初始化

方式一（推荐，脚本会提示输入口令并校验导入结果）：

```powershell
pwsh -File scripts\init-database.ps1 -Server localhost -Port 3306 -User root
```

方式二（手工执行，注意使用 utf8mb4，避免中文乱码）：

```powershell
cmd /c "mysql -uroot -p --default-character-set=utf8mb4 < database\schema.sql"
cmd /c "mysql -uroot -p --default-character-set=utf8mb4 < database\seed.sql"
```

导入后确认：

```sql
SELECT COUNT(*) FROM balance_check.sys_user;   -- 4 个演示账号
SELECT COUNT(*) FROM balance_check.balance;    -- 2 台天平
```

演示账号（口令均为 123456）：admin（管理员）、liyi / lier（检验人员）、qiyi（复核确认人员）。

## 四、后端配置

`backend/src/main/resources/application.yml` 中所有部署相关项都写成 `${环境变量:默认值}`，交付到新机器时无需改文件：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| SERVER_PORT | 8081 | 后端端口 |
| DB_URL | jdbc:mysql://localhost:3306/balance_check?... | 数据库连接串 |
| DB_USERNAME | root | 数据库账号 |
| DB_PASSWORD | 123456 | 数据库口令 |
| APP_UPLOAD_DIR | D:/develop/balance-check-data/uploads | 视频存储目录 |
| UPLOAD_MAX_FILE | 500MB | 单文件上限 |
| UPLOAD_MAX_REQUEST | 520MB | 单请求上限 |
| SESSION_TIMEOUT | 8h | 会话有效期 |

设置示例（当前 PowerShell 会话生效）：

```powershell
$env:DB_PASSWORD = 'your-password'
$env:APP_UPLOAD_DIR = 'D:\balance-check-data\uploads'
```

视频不要放在 C 盘或 OneDrive 同步目录；按每天 20 台、单条 30MB 估算约 600MB/天，建议每季度归档一次。

## 五、启动与停止

交付包内直接启动（自动等待健康检查）：

```powershell
pwsh -File scripts\start-backend.ps1 -Port 8081
```

脚本会用后台进程运行 `java -jar backend\balance-check.jar`，把日志写到 `logs/`，并把进程号写入 `logs\backend.pid`。停止：

```powershell
pwsh -File scripts\stop-backend.ps1
```

也可以手工启动：

```powershell
java -jar backend\balance-check.jar
```

健康检查：`GET /api/system/health` 返回服务状态、存储路径、磁盘容量与可写状态。浏览器打开 <http://localhost:8081>。

## 六、前端部署

开发模式（5173 端口，Vite 已把 /api 代理到 8081）：

```powershell
cd frontend
npm install
npm run dev
```

生产模式二选一：

1. 由后端托管：把 `frontend/dist` 的内容复制到后端静态资源目录（或作为独立静态目录由运维配置），访问 8081。
2. 由 Nginx 托管，后端只提供 /api：

```nginx
server {
    listen 80;
    server_name balance.local;

    root   D:/balance-check/frontend;
    index  index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        try_files $uri $uri/ /index.html;   # history 路由回退
    }
}
```

## 七、构建与校验交付包

```powershell
pwsh -File scripts\package-release.ps1                # 构建并打包，输出 dist/balance-check-<版本> 与同名 zip
pwsh -File scripts\package-release.ps1 -SkipFrontend   # 只打包后端（前端依赖未安装时）
pwsh -File scripts\verify-release.ps1 -Path dist\balance-check-0.1.0-SNAPSHOT   # 校验交付包完整性
```

打包脚本按顺序执行：`mvnw -o -DskipTests package` → `npm run build` → 复制 jar、前端静态文件、数据库脚本、文档与脚本 → 生成 VERSION.txt → 压缩 zip。离线环境依赖已经放在本地仓库，构建全程 `-o`（离线）执行。

## 八、日常运维

- 健康检查：定时请求 `/api/system/health`，关注 `storage.freeGb` 与 `storage.writable`。
- 备份：`mysqldump -uroot -p balance_check > backup\balance_check_yyyyMMdd.sql`，连同 `APP_UPLOAD_DIR` 一起备份。
- 归档：已复核记录的视频可每季度移到离线介质，数据库保留元数据即可追溯。
- 日志：后端日志在 `logs/`（start-backend.ps1 启动时），按需清理；审计日志在数据库 `audit_log` 表，管理员可在"操作日志"页查询。

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动即退出，日志提示连接失败 | 数据库未启动、口令不对或库不存在 | 先执行 init-database.ps1；核对 DB_URL / DB_PASSWORD |
| `Public Key Retrieval is not allowed` | MySQL 8 使用 caching_sha2_password | 连接串已默认 `allowPublicKeyRetrieval=true`，如自建连接串需保留 |
| 中文显示为问号 | 客户端字符集不是 utf8mb4 | 导入时加 `--default-character-set=utf8mb4` |
| 端口 8081 被占用 | 上一次后端未退出 | `scripts\stop-backend.ps1`，或换 `-Port` |
| 刷新页面 404 | 前端 history 路由未回退 | Nginx 加 `try_files $uri $uri/ /index.html` |
| 上传大文件失败 | 超过 500MB 限制 | 调整 UPLOAD_MAX_FILE 与反向代理 client_max_body_size |
| 脚本无法执行 | 执行策略 | `powershell -ExecutionPolicy Bypass -File <脚本>` |
| 离线安装前端依赖失败 | 无外网 | 在可联网机器 `npm install` 后整体拷贝 node_modules，或用内网镜像 |

## 十、卸载与回滚

1. `scripts\stop-backend.ps1` 停止后端；
2. 备份数据库与 `APP_UPLOAD_DIR`；
3. 回滚时用上一版本交付包替换，数据库结构在批次 3 之后未变更，可直接复用；
4. 确认不再需要后再删除旧目录与数据库。
